# 后台资源热替换

> 更新日期：2026-11-08。异步执行、跨会话前台切换、依赖等待、验收重试、常驻状态、用量和归档已经实现，现状见 [工作模式教学](../users/INTERACTION_MODES.md) 与 [框架原理](../developers/INTERACTION_MODES.md)。本文仅保留未实现的破坏性资源热替换。

前台空闲时已经允许切换会话、模式、模型和推理深度。旧任务继续使用捕获的执行环境；排队协调绑定原会话。后台资源仍被使用时，刷新/禁用扩展、替换 MCP、完整配置重建及删除会话保持保护屏障。

允许这些破坏性操作与旧执行重叠，需要按实际服务持有资源租约：新任务绑定新服务，旧任务在完成或取消后归还旧连接，最后一个使用者结束才销毁旧资源。MCP 退出登录等撤销操作必须立即生效，不得因保留租约而维持已撤销凭据。

验收需要覆盖同名服务替换、扩展卸载、取消排队、启动失败、重复归还和程序关闭；资源不能提前关闭，也不能因未执行任务而永久泄漏。该方向不改变重启后不自动重放操作、worktree 不自动合并的边界。
