# 子任务后续要做什么

> **主要读者：** NekoCode 项目开发者与维护者。本文只写**还没做**的子任务能力：要做什么、为什么、怎么算做完。已完成的能力写在现状文档里，不在本文重复。
>
> 更新日期：2026-10-29。完成后先把结果写进 [用户指南](../users/USER_GUIDE.md#查看子任务)、[数据目录](../users/DATA_DIRECTORY.md#subagents--子任务会话)、[Runtime 应用指南](../developers/RUNTIME_APP_GUIDE.md) 或 [Headless 契约](../developers/STREAM_JSON.md)，再把对应小节从本文删除。

## 现状边界（只列决定后续取舍的事实）

- 任务归属父会话：TUI 列表按当前父会话查询，`Subagents(filter)` 带 `SessionID`；`Runtime` 没有跨会话的任务列表接口。
- 实时正文已经流式：`subagent_engine` 发出 `text_delta`/`reasoning_delta`/`message`，经 Runtime 事件推给 TUI（`interaction/tui/tasks_stream.go`）。这一条不必再做。
- **没有删除入口**：`/sessions` 的 `d` 只在会话菜单里生效（`interaction/tui/model_handlers.go:382` 的 `requestSessionDelete` 要求输入框为 `/sessions` 且处于菜单态），任务浮层没有删除键，Runtime 也没有删除方法，任务目录只能随父会话一起清。
- 工具输出只能看不能找：预览和分页读取有，搜索和导出没有。
- 各端能力不等价：Runtime/TUI 已有任务查询与详情；GUI、HTTP 没有对应接口；headless 只发事件，没有查询方法。

## 1. 全局任务列表（跨父会话只读）

**要做什么**：`/tasks` 增加“全部已保存任务”范围，按父会话分组、分页加载；查看其他父会话的任务只读，续跑时切到所属会话并重新校验工作目录与权限。

**为什么**：现在换个会话就找不到以前的任务，用户只能靠记忆翻目录。

**关键约束**：列表不能一次加载所有任务的正文；分组和分页都走 Runtime，TUI 不直接读目录。

**算做完**：`Runtime` 提供不带 `SessionID` 的查询（或显式“全部”范围）与总分页；TUI 能切换范围并在大量任务下保持有界内存；只读查看时尝试续跑会被拒绝并说明原因。

## 2. 删除任务

**要做什么**：任务列表支持删除（`d` + 确认），删除范围包括任务记录、专属工具输出和观测缓存；排队中、执行中、等待用户处理的任务禁止删除。

**为什么**：现在只能删整个父会话，单个失败任务会一直留着。

**关键约束**：互斥必须在存储层，不能只靠 UI 状态判断；部分清理失败要可诊断、可重试，不能误删其他任务；父对话里已有的引用不随删除改写。实现前先评审删除事务与锁顺序。

**算做完**：续跑与删除并发时不破坏数据；清理中途失败重试成功；删除后访问旧记录给出明确提示。

## 3. 工具输出搜索与导出

**要做什么**：任务详情里对已保存的工具输出做搜索，并支持把某次或多轮输出导出到文件。

**为什么**：大输出目前只能翻页看，长任务里找一个报错要手工翻。

**算做完**：搜索在服务端按页进行，不把全部输出读进内存；导出走流式写入；空结果、已被淘汰的内容和文件缺失给出不同提示。

## 4. 多端接入同一份任务数据

**要做什么**：GUI 与 HTTP 按 Runtime 已有 DTO 接入任务列表、轮次和输出读取；headless/ACP 明确是否需要查询方法，而不是只有事件流。

**为什么**：Runtime 已有 `Subagents`、`SubagentAttempts`、`SubagentToolOutput`，但只有 TUI 用上，其他入口的“支持子任务”说法与实际不符。

**关键约束**：新增只读分页接口，正文与现有面向观测的摘要接口分开；缺字段的旧客户端要能降级。

**算做完**：各端对同一任务显示一致状态或明确声明不支持；未知事件、迟到事件不污染已提交结果。

## 顺序建议

1 → 2 → 3 可以各自独立提交；4 依赖 1 的查询形态先稳定。

## 验收与测试的共同要求

- 用可控假模型做并发与压力测试，不用真实模型请求代替。
- 状态只有一份权威来源：Runtime 快照、观测缓存和目录索引不得互相覆盖。
- 所有新缓存都必须可删除、可重建，缓存损坏不能导致任务丢失。
- 旧数据只读兼容，新格式写入前说明降级限制，不把代码回滚当作数据回滚。
