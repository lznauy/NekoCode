# 会话恢复、回退与备份指南

> **主要读者：** 用户及部署管理者。恢复会话、回退文件、导出和备份本机数据。

本指南区分三类操作：恢复会话继续对话，回退检查点恢复已记录的文件状态，备份数据以便以后找回。它们不能互相替代。

| 操作 | 能恢复什么 | 不会自动完成什么 |
| --- | --- | --- |
| 恢复会话 | 已保存的对话、上下文和会话状态 | 把项目文件恢复成历史版本 |
| 检查点回退 | 检查点覆盖范围内的文件状态 | 撤销远程请求、数据库操作或任意 Shell 副作用 |
| 导出 | 供外部查看和分析的对话数据 | 创建可完整恢复的应用备份 |
| 文件备份 | 备份时保存的数据和项目文件 | 自动迁移项目路径、安装版本或外部服务 |

## 一、恢复已有会话

从原项目目录启动 NekoCode，在输入框执行：

```text
/sessions
```

选择已有会话，或使用列表中的完整 ID：

```text
/sessions <session-id>
```

尖括号表示占位符，替换为真实 ID。`/sessions` 切换已保存会话，`/new` 开始新会话，不是删除旧会话。实际恢复范围以已成功保存的数据为准，未提交的进程内状态不能假定都已落盘。

会话与原项目工作目录绑定。从其他项目恢复会被拒绝；应回到原项目打开，而不是把目标会话硬绑定到另一个目录。旧记录缺少 `cwd` 时会明确报错；先备份，再根据可信记录恢复原项目的绝对路径，不能靠猜测填写。

项目移动或换电脑后，没有通用的自动路径迁移流程。恢复前尽量保持原路径及外部依赖；必须迁移时，先在备份副本上确认版本和路径约束，不要批量替换会话文件里的路径。

## 二、恢复子任务的边界

TUI 用 `/tasks` 或 `Ctrl+G` 查看当前父会话的子任务。需要继续任务时，让主 Agent 使用 `task_list` 查询，再把条目的 `items[].id` 作为 `task.resume_id`。

`latest_attempt.id` 是某次执行轮次的 ID，不能当作子任务 ID。运行中的任务不能重复续跑；省略 profile、skills 时按已保存记录复用，profile 必须保持一致。

已开始任务的上下文会按实现保存；尚未开始的等待队列只在内存中，重启后不会重放。恢复父会话也不等于自动继续执行所有子任务。子任务后续阶段的设计见 [规划目录](../plan/README.md)。

## 三、回退检查点

先结束或取消正在执行的修改，再在 NekoCode 输入框查看 `/rewind` 菜单。选择菜单中对应的用户消息和改动摘要，或使用已确认的检查点 ID：

```text
/rewind <checkpoint-id>
```

直接提交不带参数的 `/rewind` 会按实现选择默认目标，并非纯查询；想先查看目标，使用菜单。回退前保留你需要的当前改动，例如在项目版本管理中保存，或另行复制工作区。

检查点记录受支持写入链路触及文件的改动前状态，不是整个磁盘的快照。Shell、第三方工具和外部程序修改的文件不能一概假定已被捕获；Git 提交、远程服务和数据库变更也不在文件回退范围内。

回退后检查返回结果和文件实际内容。对话不会被倒删成旧状态，系统会追加回退事件，让后续执行知道文件已变化。相关读取证据和缓存会失效，需要重新读取文件。

如果报告部分回退或持久化错误，保留现场和日志，核对哪些文件已经变化，不要根据一个错误结果就认定完全没有副作用。排查见 [故障排查指南](TROUBLESHOOTING.md)。

## 四、导出对话

在 NekoCode 输入框执行：

```text
/export
```

默认输出到 `~/.nekocode/exports/nekocode-context.json`，具体路径以返回消息为准。需要长期保留多个导出时，及时另存为不同文件名，避免后一次导出覆盖同一路径。

导出用于查看或交给外部工具，不是完整恢复镜像；当前没有把该导出文件直接当作完整会话备份导入的教程入口。导出可能包含代码、工具输出和消息内容，分享前检查内容。

## 五、备份哪些内容

先停止使用该用户数据目录的全部 NekoCode 实例，包括 TUI、GUI、daemon 和后台连接器，避免复制到不同提交时刻的文件组合。

| 内容 | 为什么保留 |
| --- | --- |
| `~/.nekocode/sessions/` | 会话快照、当前上下文、完整历史及会话内运行记录 |
| `~/.nekocode/checkpoints/` | 文件回退所需数据 |
| `~/.nekocode/subagents/`、`~/.nekocode/tool-results/`（存在时） | 子任务和工具结果引用；保留实际版本生成的目录 |
| `~/.nekocode/config.json`、`plugins/`、`skills/` | 用户配置和扩展 |
| `~/.nekocode/credentials/` | 本机外部服务凭据；恢复后仍可能需要重新授权 |
| 项目源码、`NEKOCODE.md` 和项目 `.nekocode/` | 实际工作区，以及项目配置、扩展和本机授权记录 |

目录布局会随版本变化。最省事的方式是完整备份用户 `.nekocode`，另外备份项目；不要只挑一个 `session.json`。会话当前上下文采用双槽文件并配合提交水位，文件之间有一致性关系。

运行事件有保留窗口，不会永久保存。需要长期保留某次诊断时，应及时备份对应运行记录。目录细节见 [数据目录说明](DATA_DIRECTORY.md)。

### 本机备份示例

下面是 Linux/macOS Shell 示例，应用应先关闭。操作只创建归档，不修改源数据：

```bash
set -eu
umask 077
backup_dir="$HOME/nekocode-backups"
mkdir -p "$backup_dir"
backup_file="$backup_dir/nekocode-$(date +%Y%m%d-%H%M%S).tar.gz"
tar -czf "$backup_file" -C "$HOME" .nekocode
tar -tzf "$backup_file" > /dev/null
printf 'Backup: %s\n' "$backup_file"
```

确认 `tar` 两步都成功后再使用该归档；后面的输出不是成功判据。该归档包含凭据和个人配置，应按私有备份保存。另行备份项目工作区；Git 未跟踪和被忽略文件不一定存在于远程仓库中。

### 先解压检查，再恢复

设置 `backup_file` 为自己可信备份的绝对路径，在独立目录检查：

```bash
set -eu
restore_dir="$(mktemp -d)"
tar -xzf "$backup_file" -C "$restore_dir"
printf 'Inspect restored data: %s/.nekocode\n' "$restore_dir"
```

确认解压成功、目录结构完整且应用仍关闭后，再选择替换用户数据。先保留现有目录，避免直接覆盖合并两个版本：

```bash
set -eu
previous_data="$HOME/.nekocode.before-restore-$(date +%Y%m%d-%H%M%S)"
if [ -d "$HOME/.nekocode" ]; then
  mv "$HOME/.nekocode" "$previous_data"
fi
cp -a "$restore_dir/.nekocode" "$HOME/.nekocode"
```

每一步失败都应停止，保留原目录与备份。恢复项目文件并核对其原绝对路径，再使用与备份格式兼容的应用版本启动。检查会话列表、目标会话、扩展与授权是否正常；在确认前不要删除旧目录。

这些归档命令不提供加密、异地复制或保留策略，需要长期备份时另行纳入自己的备份流程。

## 六、清理前先确认影响

不要把“腾空间”和“修复会话”混为一谈：删除数据一般不能修复原来的故障证据。

- 删除 `sessions/` 会丢失会话内容；删除 `checkpoints/` 会失去相应回退能力。
- 删除运行事件或日志会丢失诊断和统计依据，不能保证从对话文本重建。
- 删除凭据需要重新授权；删除权限记忆会改变后续审批行为。
- 临时文件也可能被尚未完成的图片输入或工具结果引用；清理时先关闭相关实例。

完整删除影响见 [数据目录的可删除性说明](DATA_DIRECTORY.md#可删除性)。本指南不提供“一键清空用户目录”的命令。
