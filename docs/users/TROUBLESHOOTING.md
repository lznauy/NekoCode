# 故障排查指南

> **主要读者：** 用户。定位使用中的故障、收集诊断信息；实现缺陷由项目开发者进一步处理。

按“入口 → 配置 → 模型或扩展 → 具体调用 → 保存结果”的顺序定位。先记录错误和最小复现，再修改配置；不要同时改动多项后仅凭现象消失判断原因。

## 一、先留下这些信息

记录使用版本或构建提交、系统与架构、启动目录、入口（TUI、GUI、Headless、ACP、HTTP 或 IM）、报错时间，以及能够复现的最短操作。

应用日志默认在 `~/.nekocode/logs/`。会话和运行记录的位置见 [数据目录](DATA_DIRECTORY.md)。提交问题时提供相关时间窗口内的错误，隐藏密钥、凭据、私有代码及消息内容；不要直接上传整个配置或用户数据目录。

## 二、按现象找入口

| 现象 | 先检查 | 下一步 |
| --- | --- | --- |
| 终端找不到程序 | 终端执行 `command -v nekocode-tui`，检查 `~/.local/bin` 是否在 PATH | 对照 [安装说明](USER_GUIDE.md#一安装) |
| 一启动就退出或崩溃 | 启动输出、日志、系统架构与实际二进制 | 源码安装对照 [构建说明](../../build/README.md) |
| 能启动但模型调用失败 | 当前模型、API Key、base URL、协议及服务端错误 | 按第三节逐项缩小范围 |
| 改配置没有效果 | 修改的文件来源及该配置生效方式 | 查看 `/workspace`，按需刷新或重启 |
| 工具被拒绝 | 审批结果、权限规则、工作区范围与 Hook 原因 | 不要通过放宽全部权限来隐藏原因 |
| Skill、Agent 或 Hook 不可用 | 插件启用状态、当前项目、名称冲突及加载错误 | 按第四节排查 |
| 显示等待且没有结果 | 是否在等审批、问题回答、排队或外部命令 | 查看任务状态，确认等待对象 |
| 索引初始化失败、查不到代码或结果过时 | 执行 `/index status`，核对根目录与监听状态 | 执行 `/index rebuild`；失败时保留错误和输出中的备份路径 |
| 会话无法恢复 | 原项目目录、会话文件是否完整 | 见 [会话恢复指南](SESSION_GUIDE.md) |

表中的 `/workspace`、`/model` 等命令应在 NekoCode 输入框执行，不能直接在 Shell 中运行。

## 三、模型调用失败

先用一个短文本请求验证基础对话，再逐步加入工具、图片和子任务，确认故障发生在哪一层。

1. 使用 `/model` 确认当前选择。配置中 `active` 使用 `服务名/模型名或别名`，例如 `deepseek/default`，必须对应 `providers` 中的一条模型记录。
2. 核对该条目的 `api_key`、`base_url`、`model`、`protocol`。OpenAI 兼容接口和 Anthropic 接口不能只改一个模型名就互换。
3. 根据返回的状态码和错误文本检查认证、额度、地址、模型可用性及网络；保留服务端原始错误，不根据“超时”直接推断密钥无效。
4. 普通文本成功后再尝试工具或图片。确认所选模型及其协议确实支持对应能力，避免同时混入多个变量。

模型配置的完整示例见 [用户指南](USER_GUIDE.md#二首次配置接入模型)。从文件手动修改配置后，按该字段的说明重启或刷新；不要把 `/workspace reload` 当作所有全局模型设置的通用热加载入口。

## 四、扩展没有生效

先执行 `/plugin list` 和 `/plugin info <插件名>`。确认实际安装目录、启用状态以及 Agent、Hook 加载错误。安装成功只说明文件已安装，不代表每项能力都能运行。

| 扩展 | 常见原因 | 详细指南 |
| --- | --- | --- |
| Skill | frontmatter 解析失败、名称不同、被高优先级同名技能覆盖，或当前对话还保留旧正文 | [Skill](../developers/SKILL_GUIDE.md) |
| Agent | 工具超出 base、未知字段、路径不正确，或短名称存在歧义 | [Agent](../developers/AGENT_GUIDE.md) |
| Hook | 未重载 JS、事件或 matcher 不匹配、JSON 输出格式错误、超时 | [Hook](../developers/HOOK_GUIDE.md) |
| Plugin | 修改了源目录而非安装副本，或其中一个 Agent、Hook 校验失败阻止整体激活 | [Plugin](../developers/PLUGIN_GUIDE.md) |
| MCP | 进程启动失败、服务未连接、OAuth 未完成、工具尚未发现 | [MCP 配置](USER_GUIDE.md#七mcp-服务) |

项目 Skill 可执行 `/workspace reload` 刷新。插件源目录修改后重新安装；安装副本修改后，在任务结束时禁用再启用或重启。不要反复 enable 一个已经正常启用的插件来代替重载。

## 五、工具拒绝、等待或卡住

先区分以下状态：

- **权限或 Hook 拒绝**：查看具体工具名、理由和匹配规则。已有文件修改前，需要当前执行者通过专用读取工具获取读取依据；父 Agent 或兄弟 Agent 的读取不能代替。
- **等待审批或问题回答**：在当前 UI 完成对应交互。Headless 宿主必须保持 stdin 打开并回复控制请求；stdin 关闭会自动拒绝交互。
- **子任务排队**：TUI 用 `/tasks` 或 `Ctrl+G` 查看。排队未开始不等于执行卡死；进程重启不会重放内存队列。
- **外部调用未结束**：检查工具开始记录后的日志、进程或网络等待。先取消当前任务并观察终态，再决定是否重试，避免重复提交有副作用的操作。

Hook 日志可在终端中检索：

```bash
rg 'hook_audit|hook_command|hook_resolved' ~/.nekocode/logs/
```

使用 `run_id` 定位一次运行，再结合事件、工具或 `evaluation_id` 关联。结束结果中的失败、取消、部分完成要分别处理，不能只看是否产生了一段文本。

进程内自定义 Go 工具和回调必须主动响应 context；取消请求不保证任意第三方代码立即停止。实现方应按 [工具开发指南](../developers/TOOL_GUIDE.md) 检查取消链路。

## 六、上下文、历史和回退问题

`/context` 用于查看上下文占用，`/compact` 请求摘要。摘要会改变模型当前可见上下文，不等于删除完整历史，也不能恢复已经丢失的文件。

历史加载慢、恢复失败或回退异常时，先备份完整相关数据，保留错误日志和文件组合，不要手改 `transcript.jsonl`、截断文件或只复制一个 `session.json`。具体流程见 [会话恢复、回退与备份](SESSION_GUIDE.md)。

## 七、向维护者提供可用的问题报告

提供最短复现、预期与实际结果、版本及入口、脱敏错误，以及是否能在不加载自定义扩展的新会话中复现。说明已经尝试的修改，避免维护者重复排查。

范围和渠道见 [支持说明](../policy/SUPPORT.md)。安全漏洞使用 [安全策略](../policy/SECURITY.md) 中的私有渠道，不在公开问题中附带敏感材料。

### 使用域名白名单时无法联网

查看审批卡和该次 Shell 输出中的目标域名。确认 `outbound_domains` 包含实际访问的精确域名（含重定向后的目标）；空数组表示禁止联网。仅支持 HTTP 80 与 HTTPS 443，私网地址及宿主本地服务会被拒绝。

如果提示 `required network isolation unavailable`，当前环境无法建立所需的 Linux 原生隔离；不会自动改用 Landlock 或宿主执行。不要把删除白名单当作等价修复，这会改变授权边界。依赖 Unix socket、io_uring 或不支持 HTTP 代理的程序也可能无法在此模式运行。细节见 [Shell 网络域名限制](../developers/NETWORK_EGRESS.md)。
