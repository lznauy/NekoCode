为包裹中转站团队交付 Relay Station，一个能在断网、进程重启以及多个操作员同时发运时使用的 Python 3 标准库项目。以工作区 CONTRACT.md 为外部接口契约，实现其全部业务操作。最终提交可直接从当前目录运行的 `python3 -m relay`、SQLite 持久层、项目测试和用户文档。

这次也验收协作过程。你是负责最终交付的主代理。组织约 16 位子代理，至少 12 个不同的子任务须有实质工具工作并成功交付，其中至少 8 名最终成功的执行者须同时处于运行态。尽量把 12 个互不依赖的实现或测试任务放进同一个并行工具调用批次；等待、重试和复用同一执行者均不增加人数。当前为 standard 模式，同批使用多个 task 调用。共享工作区中按文件划定唯一写入者，让每个子任务在交接时说明接口、产物、验证和已知缺口。

按以下依赖推进，可依项目情况调整分工。
- 设计阶段由架构和业务设计负责人先确定目录、存储模型、事务边界、状态机和模块接口；主代理确认接口后再分发写任务。保留一份与最终实现相符的 docs/design.md。
- 实现与测试阶段可以并行分给十二位负责人：CLI 协议与错误处理、数据库与事务、网络导入、选路、包裹创建、运输状态转换、幂等、台账与报表、路由与导入测试、状态机测试、并发与重启测试、CLI 端到端测试。先明确跨模块调用签名、输入输出、文件归属，避免多人同时改同一入口。运行整套测试时会集成这些模块。
- 集成阶段由独立负责人复核事务与故障恢复，再由发布负责人核对文档与可运行命令。主代理处理集成缺口，汇齐所有子任务后，在最终工作区独立运行一条 shell 命令 `python3 -m unittest discover -s tests`，必要时修复并重跑，最后报告实际测试结果、并发协作和剩余风险。

项目规模按 relay/ 与 tests/ 下的自写 Python 源码计算：至少 1000 个有效物理代码行，其中生产实现至少 500 行。空行、注释和独立说明字符串不计。优先用真实边界、故障恢复和回归测试达到规模，避免重复或填充代码。
README.md 给出可直接执行的 CLI 与测试示例。docs/design.md 说明目录分工、功能设计、CLI 到存储的调用路径、SQLite 事务、重试和验证策略；用相对于文档目录的 Markdown 链接关联至少三个实际生产模块与两个测试文件。至少提供 12 个实际通过的 unittest 用例，其中至少一个通过子进程调用 route 并断言返回的 minutes。保留原始 CONTRACT.md。
