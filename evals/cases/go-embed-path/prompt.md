分析 repo/ 中固定版本 Go 的 //go:embed 数据流。假设包内 assets/ 有 a.txt 和 .secret 两个普通文件，指令只写目录 assets。对比 all:assets；再分析将两个文件嵌入单个 string 的结果，以及已构建的 embed.FS 读取缺失文件的结果。项目只读，不需要构建整个 Go。最终只返回 JSON 对象，四个键为 matching、handoff、compile、lookup。每项包含 explanation（中文因果说明）、value（下列问题的精确答案）和 refs（若干 {"file":"相对 repo 的路径","line":行号}，引用决定行为的实现语句）。matching.value 是普通目录模式纳入的文件名数组；handoff.value 是构建器传递给编译器的配置含有哪些映射字段（名字数组）；compile.value 是 string 多文件的结果（build_error 或 success）；lookup.value 是缺失文件错误可匹配的 fs 包哨兵名（含 fs. 前缀）。依次引用目录遍历的排除判断、构建器填充映射、编译器多文件检查以及运行时缺失分支。
