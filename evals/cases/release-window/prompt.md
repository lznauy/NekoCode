发布值班员拿到的原型按输入顺序串行排程，交接时有人据此低估了上线时间。请修复并交付可复用的离线排程工具，只用 Python 3 标准库。保留调用方式 `python3 planner.py BUNDLE OUTPUT`，从任意当前目录均可运行。

每个 BUNDLE 都有三份 UTF-8 输入。plan.json 的 jobs 含唯一非空字符串 id、crew、正整数 minutes 及前置任务 ID 数组 needs。changes.jsonl 可为空，或含乱序的工时修订，每行含已知 id、正整数 rev 和正整数 minutes；忽略空行。每项取最高 rev，同一 id 和 rev 工时相同视为重复，工时不同则整批失败，即使该版已过期。windows.csv 表头为 crew,start,end，每行是该班组不能作业的半开区间 [start,end)，0 <= start < end，单位为整数分钟。重叠、相接及乱序窗口均有效。

调度从 0 开始。每轮考虑所有前置已被排入计划的任务，其最早开工时间同时受前置结束时间、本班组上一项任务结束时间、全部禁作窗口约束。任务不得拆分。选取最早开工者，平局按 id 的 Unicode 字典序，追加到计划；不同班组可以同时工作。结束恰好等于禁作窗口起点有效。没有任务时完工时间为 0。

成功时退出 0 并把 JSON 写入 OUTPUT，格式为 {"schedule":[{"id":"…","start":0,"end":2}],"finish":2}，数组按调度选择顺序。遇到未知依赖、循环依赖、未知修订对象、冲突修订或非法工时（包括布尔值）时退出非零，保留已有 OUTPUT 的原始字节；若原先没有 OUTPUT 则不生成。输入均需原样保留。

请把实际 incident/ 三个输入的排程交付在 handoff.json。另在 tests/ 下提供可用 `python3 -m unittest discover -s tests` 运行的回归测试，请通过 CLI 验证不同班组能够并行，即使错误版本保留所有输出字段，你的测试也应发现它将可并行的任务串行化。验收还会用其他班次的数据运行同一个入口。
